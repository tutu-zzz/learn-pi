## 2026-09-29

### V0.1 — 第一次 LLM 调用

**状态：测试通过**

`micro-pi` 已完成第一次终端模型对话，能够读取用户输入、调用 `DeepSeek-V4.1-Flash`，并输出模型回答。

```text
加载配置
  → 构造消息
  → 发出 HTTP 请求
  → 提取模型回答
```

| 阶段 | 代码范围 | 作用 |
|---|---:|---|
| 加载配置 | 6–18 行 | 加载 `.env`，读取并检查 Base URL、Model 和 API Key |
| 构造消息 | 21–22、41–48 行 | 获取用户输入，构造 `system` 和 `user` 消息 |
| 发出 HTTP 请求 | 24–39、50–58 行 | 准备 URL、请求头，发送 JSON，并检查 HTTP 状态 |
| 提取模型回答 | 60–63 行 | 解析响应 JSON，取出并打印回答 |

验收结果：

- `.env` 配置加载正常。
- HTTP 请求与响应解析正常。
- 模型成功返回预期内容。
- 终端未输出 API Key。

## 2026-10-08

### V0.2 — Conversation

**状态：测试通过**

`micro-pi` 已支持同一次程序运行中的多轮对话，能够通过重复发送消息历史记住前文。

```text
创建消息历史
  → 读取用户输入
  → 追加 user 消息
  → 发送完整 messages
  → 提取模型回答
  → 追加 assistant 消息
  → 进入下一轮
```

| 阶段 | 代码范围 | 作用 |
|---|---:|---|
| 创建消息历史 | 39–45 行 | 在循环外创建 `messages`，保存整个会话的消息 |
| 多轮对话循环 | 48–57 行 | 持续接收用户输入，并通过 `/exit` 结束会话 |
| 记录用户消息 | 59–65 行 | 将本轮 `user` 消息追加到历史 |
| 发送完整上下文 | 67–82 行 | 将完整 `messages` 放入请求体并调用模型 |
| 记录模型回答 | 85–98 行 | 提取回答，追加 `assistant` 消息并输出 |

验收结果：

- 第一轮告诉模型“我叫小明”。
- 第二轮询问名字时，模型正确回答“小明”。
- 输入 `/exit` 后程序正常结束。
- 当前记忆只存在于程序运行期间，尚未实现跨进程 Session。
